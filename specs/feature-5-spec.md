# Feature 5 명세 — 평일 08:00 자동 실행 판단

근거 문서: [App_기획서.md](App_기획서.md) (제약 — "사람이 실행하지 않은 경우에 한해 공휴일이 아닌 평일 오전 08:00에 자동 실행한다"), [feature-3-spec.md](feature-3-spec.md), [feature-4-spec.md](feature-4-spec.md)

## 무엇을 하는 기능인가

오늘 사람이 이미 수동으로 실행했는지를 확인해서, 아직 안 했고 평일 08:00가 지났으면 근태 요약 파이프라인(Feature 1~3)을 자동으로 실행하는 기능. 자동 실행된 경우엔 사람 확인(Feature 4의 y/n)을 생략하고, 결과를 파일로 남겨 나중에 사람이 확인하게 한다. 수동 실행 경로에도 "오늘 실행됨" 기록을 남기는 부분을 포함한다.

## 입력

- 오늘 날짜·요일·현재 시각 (시스템 값)
- 실행 상태 파일 경로 (예: `last_run.txt` — 마지막으로 실행 완료된 날짜만 기록)
- 근태 요약 파이프라인(Feature 3) 결과

## 동작

1. 오늘이 평일(월~금)인지 확인한다. 주말이면 아무것도 하지 않고 종료한다. (공휴일 여부는 이번 범위에서 판단하지 않는다.)
2. 상태 파일을 읽어 마지막으로 기록된 실행 날짜를 확인한다.
3. 그 날짜가 오늘과 같으면(=오늘 이미 실행됨, 수동이든 자동이든) 아무것도 하지 않고 종료한다.
4. 오늘 아직 실행 기록이 없는 경우, 현재 시각이 08:00 이후인지 확인한다.
   - 08:00 이전이면 아직 자동 실행 시점이 아니므로 아무것도 하지 않는다.
   - 08:00 이후면 자동 실행 조건을 만족한 것으로 판단한다.
5. 자동 실행 조건을 만족하면 Feature 3(파일 자동 인식 + 요약 텍스트 생성)을 실행한다.
   - 오늘 근태 파일을 못 찾으면 안내 메시지만 남기고 종료한다 (상태 파일은 갱신하지 않는다 — 아직 "실행 완료"가 아니므로 내일 다시 이 시각에 시도할 수 있어야 한다).
   - 요약 텍스트가 만들어지면, 사람 확인(Feature 4) 단계는 생략하고 결과 텍스트를 파일로 저장한다.
   - 상태 파일에 오늘 날짜를 기록한다.
6. 사람이 08:00 이전에 수동으로 먼저 실행해서 Feature 4 확인까지 마치고 승인(y)한 경우에도, 그 시점에 상태 파일에 오늘 날짜를 기록한다. (그래야 이후 08:00 자동 실행이 같은 날 중복 실행되지 않는다.) 거부(n)한 경우에는 기록하지 않는다 — 데이터를 다시 확인해야 하는 상태이므로, 사람이 고치지 않고 방치하더라도 08:00 자동 실행이라는 안전망이 계속 작동하게 하기 위함이다.

## 출력

- 오늘이 주말이거나 이미 실행 기록이 있는 경우: 별도 출력 없이 조용히 종료
- 자동 실행 조건을 만족해 실행한 경우: 근태 요약 텍스트가 담긴 결과 파일 1개 (예: `outputs/today-summary-YYYYMMDD.txt`) + 상태 파일 갱신
- 오늘 근태 파일을 아직 못 찾은 경우: 안내 메시지만 출력 (상태 파일은 갱신하지 않음)

## 지금은 뺄 것

- 공휴일 목록 관리 및 판단 (이번엔 평일 월~금 여부까지만 확인)
- Windows 작업 스케줄러(Task Scheduler) 등에 실제로 매일 08:00마다 이 판단 로직 자체를 실행시키는 등록 작업 — "지금이 실행 조건에 맞는지" 판단하는 로직까지만 만들고, 그 로직을 몇 분 간격으로든 언제 호출할지는 사람이 OS 스케줄러로 직접 설정한다.
- 자동 실행 후 저장한 결과 파일을 사람이 실제로 확인했는지 추적하는 것
- 상태 파일 외의 추가 로그·이력 관리
- 상태 파일이 손상되었거나 형식이 깨졌을 때의 복구 처리
